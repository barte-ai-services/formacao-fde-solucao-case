Dois runtimes

1 · Worker
A, C, D e E, com Cron Claude nos agentes C, D e E
  • Cron, API e conferência.
  • Regra no código do domínio; Clef pelo binding do Workers AI.
  • Motor de decisão (A) sem Claude. Dossiê, auditor e tratativa (C, D, E) são módulos com um laço de tool use pela API do Claude, rodando no Cron.
  • As tools dos agentes são a própria API da solução.
  • API do Claude, com a chave da Anthropic num secret do Worker (BARTE_ACADEMY_ANTHROPIC_API_KEY).
2 · Máquina do analista · Claude Desktop
Agente B, com MCP, MCP App e Skill MCP · MCP App · Skill
  • O agente B roda no Claude Code do analista, na máquina dele: o mesmo laço do Agent SDK, com a assinatura dele.
  • O analista decide a fila e delega ao motor sem sair do Claude.
  • O MCP App mostra a fila, a proposta e o relatório na conversa.
  • A Skill orienta o Claude (agente B).
  • Fala só com o MCP, e o MCP chama a API no Worker: a mesma que os agentes usam como tools.

O pipeline

1 · CapturaCron, SEFAZ
2 · Regraconfere e classifica
3 · Propostanível pela régua
4 · Motor (A) e auditor (D)em paralelo
5 · Dossiê (C)para quem decide
6 · Decisãono Claude (B) ou na web
7 · Pedido ao fornecedor (E)uma pessoa envia
8 · Base de critérioso raciocínio volta (#139)

Regras que valem para todos

1Nenhum número vem do texto do modelo: vem do banco.
2Diretoria e bloqueio nunca são aprovados por máquina.
3A régua é a fonte do encaminhamento: o nível só sobe, nunca desce.
4Só o Worker fala com o banco: RLS sem política, e o MCP chama a API.
5E7: a regra liga a nota ao pagamento já feito, sem pessoa. O encaminhamento segue a régua (coordenação).
6A aprovação vale uma vez: pela regra (o match), por uma pessoa do nível certo ou pelo motor dentro dos critérios (confiança de 0,98, até R$ 20 mil, depois do modo sombra). Diretoria e bloqueio são sempre de uma pessoa.
