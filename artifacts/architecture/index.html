A camada de LLM

Sem LangChain e sem framework de agente. Uma chamada à API por papel, com o SDK oficial anthropic em Python. Dois caminhos, e um deles é o padrão.

PadrãoO backend monta o contexto

Lê o bancoNota, ordem, cadastro e contagem, pelos contextos.
→
messages.parseSystem fixo do papel, com cache. Os dados vão na mensagem.
→
Schema PydanticRecomendação, justificativa, evidências e confiança.
→
O backend validaContrato e regras. Recusa, ou saída fora do contrato, vai para a pessoa.
→
GravaComo recomendação, nunca como decisão.

Quando precisa explorarO modelo busca pelo MCP

O backend pergunta"Qual destas ordens a nota cobra?", sem a lista toda.
→
Conector MCP da APIO modelo chama as tools de leitura do ja-chegou-mcp. Beta.
→
Mesmo schemaOrdem provável, evidências.
→
A regra confirmaO backend valida e grava, como no padrão. O MCP não escreve.
# papeis/recomendar.py · roda no Cron do /api
client = AsyncAnthropic()  # chave em secret do Worker

resp = await client.messages.parse(
    model="claude-opus-5-5",
    max_tokens=8000,
    output_config={"effort": "medium"},
    system=[{"type": "text", "text": PROMPT_RECOMENDAR,
             "cache_control": {"type": "ephemeral"}}],
    messages=[{"role": "user", "content": contexto.model_dump_json()}],
    output_format=Recomendacao,  # Pydantic
)
if resp.stop_reason == "refusal" or resp.parsed_output is None:
    return para_a_pessoa(nota)
rec = conferencia.validar(resp.parsed_output, nota)  # contrato e regras
await repo.gravar_recomendacao(rec)  # o modelo não toca no banco

Onde cada agente roda

Os nós da página "Onde entra agente". Todos rodam no Cron do /api, disparados por um estado novo no banco.

Agente que iremos construir
Confirmar ou alterar a ação
ClefLLMPessoa
  1. Clef, no contexto Conferência: refaz a conta com a nota, a ordem, o cadastro e a contagem, e calcula a confiança pelos fatores.
  2. Passou nas travas e no limite (até R$ 20 mil, 0,98)? Confirma como o usuário agente. O banco recusa qualquer outra coisa.
  3. Não passou? O papel Recomendar chama a API e grava a recomendação com o porquê.
  4. A pessoa decide no Astro. Diretoria e bloqueio, sempre ela.
Roda duas vezes: quando a proposta é registrada, antes da doca, e quando a contagem entra no banco.
Classificar a divergência
RegraLLM
Conferência, com o papel Classificar quando o SKU vem vazio. Achar a ordem provável entre várias usa o caminho do MCP.
Dispara: nota fiscal recebida.
Propor a ação na doca
RegraLLM
A ação sai da tabela por exceção na Conferência. O papel Dossiê escreve o texto para quem aprova.
Dispara: nota conferida.
Contar a mercadoria
LLM com visãoPessoa
A foto vai para o Storage. O papel Contar manda a imagem à API. A contagem fica no Recebimento, ao lado da do operador.
Dispara: foto da doca enviada.

O que mudou na proposta

ConferidoO SDK roda no Python Workeranthropic 2.8 com AsyncAnthropic chamou a API dentro do pywrangler dev. O cliente síncrono não serve no Worker. Falta testar com o deploy.
AjusteA chamada roda no CronUma chamada com raciocínio leva segundos. Fica fora da requisição da tela e do webhook do banco.
AjusteA confiança da LLM não decideÉ autodeclarada. Vai para a tela. Quem confirma é a confiança do Clef, calculada pelos fatores.
AjusteO MCP só lêNa referência, ele registrava a proposta. Aqui, quem grava é o backend, depois de validar.
AjusteEsforço explícitoNo claude-opus-5-5, o raciocínio não desliga e o padrão é medium. Vale low para classificar e medium para recomendar.
AjusteCache só com 512 tokensO system abaixo disso não entra no cache, e sem erro. Conferir em cache_read_input_tokens.
Em abertoO Clef confirmar muda a regra 8O modelo de domínio diz que o agente nunca aprova. Confirmar dentro do limite é a oportunidade 2, ainda a validar com a Já Chegou.
O banco lê, o backend monta o contexto, a LLM recomenda, o backend valida, o Clef confirma o que passa nas travas, e a pessoa decide o resto.
